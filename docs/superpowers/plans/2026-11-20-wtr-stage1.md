# wtr 段階 1 (ファイルの表示) 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 状態ファイル (または引数のファイル) を見張り、書かれたファイルを色付き・行番号・折り返しつきで表示し、j/k でスクロールし、o / O で外のツールを同じ画面で開き、タブごとに位置を覚える TUI `wtr` を作る。

**Architecture:** 1 つの crate (bin `wtr` と、試験のための lib)。読み込み (分類、整形、画像の復号) は別のスレッドで行い、結果を 1 本の mpsc の通り道でメインのループに渡す。メインのループは入力、ファイルの変化、読み込みの結果を受け、`App` (端末に触らない純粋な状態) を更新して ratatui で描く。色付けは syntect で先頭から少しずつ進め、まだのところは色なしで描く。

**Tech Stack:** Rust (edition 2024), ratatui 0.30 (`ratatui::crossterm` を使う), syntect 5.3 + two-face 0.5, ratatui-image 11.1, image 0.25, resvg 0.50, csv 1.4, notify 8.2 + notify-debouncer-mini 0.7, serde_json, unicode-width 0.2, clap 4.6, nix flake。

**Spec:** `docs/superpowers/specs/2026-11-20-wtr-design.md` (段階 1 の部分だけ。段階 2 の作業履歴、`--session`、`Tab` の切り替えは作らない)。2026-11-23 の設計書の変更 (gh-dash を `wtr` から外す、タブの中でファイルごとに位置を覚える、HTML の `O` は段階 1 では nvim) を反映した

## Global Constraints

- Rust で書く。TUI は ratatui。crossterm は別に依存に入れず `ratatui::crossterm` を使う (版の食い違いを避ける)
- 動かす環境は macOS (aarch64)。herdr のターミナルは Kitty graphics を表示できる
- nix でビルドできる形にする。`Cargo.lock` と `flake.lock` をコミットする。この機械には cargo が PATH に無いので、cargo のコマンドはすべて `nix develop -c cargo ...` で動かす
- 色は catppuccin-macchiato。syntect のテーマは two-face の `EmbeddedThemeName::CatppuccinMacchiato`
- アイコンは Nerd Font のマーク。固定の文言は英語かマークにし、日本語を使わない。中身として出る文字はそのまま出す
- 外のツール: nvim、csvlens、fx。見つからなければ、その旨 (`<tool> not found`) を出して何もしない
- HTML の `O` は段階 1 では nvim で開く (ブラウザーに開かせるのは段階 2。設計書 2026-11-23 の判断)。HTML 用の `FileKind` は作らない (`Text` に入り、`O` は「それ以外」の nvim になる)
- gh-dash は開かない。preview の別の枠に常駐し、`wtr` は関わらない (設計書の「目標にしないこと」)
- `q` は終了しない。終了は `ctrl-c` だけ
- 状態ファイルは読むだけ。書かない
- 状態ファイルの形: `{ "tab": "<タブを表す文字>", "file": "/abs/path", "session": "..." }`。段階 1 では `session` を読み捨てる
- 段階 2 (作業履歴、`--session`、`Tab`、delta の差分、ブラウザーに開かせること、`--on-browse`、`--icon-width`、`scan-records`) は作らない。初めての `tab` の値で作業履歴の表示から始める決まりと、`session` が変わったら作業履歴の選択を捨てる決まりも段階 2 で作る (段階 1 はファイルの表示しか無い)

|---|---|

| two-face の言語の名前 | `flake.nix` → `Nix`、`*.yaml` / `*.yml` → `YAML`、`*.md` → `Markdown`、`.zshrc` / `*.zsh` / `#!/bin/bash` → `Bourne Again Shell (bash)`、`Dockerfile`、`Makefile`、`CMakeLists.txt` も拾う。`*.jsonl`、`justfile`、`*.kdl`、拡張子の無いファイルは拾わない |
| 色付けの速さ | release ビルドで Rust のコード 4 MiB (63,550 行) に 2.3 秒。`PLAIN_THRESHOLD` = 4 MiB のままで、少しずつ進める作りなら固まらない |
| ratatui 0.30 の全角 | 全角の 2 セル目の symbol は `" "` (空白) |
| notify (FSEvents) | `/var/folders/...` の一時フォルダの変化は `/private/var/folders/...` で届く。親のフォルダを見張れば、その場の書き込み、rename による置き換え (一時ファイルと本体の両方のパス)、削除をすべて拾う。debounce 50ms で届くまで約 65ms |
| resvg 0.50 | `usvg::Options::fontdb_mut().load_system_fonts()` は 140ms (946 書体)。1 回だけ読んで使い回す |
| ratatui-image 11.1 | `Picker::halfblocks()`、`Picker::new_resize_protocol(DynamicImage) -> StatefulProtocol`、`StatefulImage::<StatefulProtocol>::default()`、`Picker::set_protocol_type` がある。Kitty は Unicode placeholder (`U+10EEEE`) で描く。herdr の資料は「Kitty graphics と Unicode placeholder を表示する」と書いている |
| herdr のターミナルの問い合わせ | herdr では、セルの大きさ (`CSI 16t`) と読み終わりの合図 (`CSI 5n`) には herdr-core がすぐ答える。Kitty の問い合わせと DA1 (`CSI c`) には、表示中なら窓の側が遅れて答える。そのため `Picker::from_query_stdio()` は、合図を受けて Kitty の返事より先に読み終え、`Halfblocks` を返す (表示中のペインで 242µs)。読み終えた後に `ESC _Gi=31;OK ESC \` と `ESC [?62;22c` が届いて入力に漏れる。セルの大きさは、表示中なら本物 (14x31)、表示していないと仮の値 (10x20)。環境変数は `TERM_PROGRAM=ghostty`、`TERM=xterm-256color`、`HC_TERMINAL_ID` など。yazi は `TERM_PROGRAM=ghostty` で Kitty を選ぶ。以上から Task 13 で、`TERM_PROGRAM=ghostty` のときは Kitty と Sixel の問い合わせを送らずに (`blacklist_protocols`) セルの大きさだけを聞き、Kitty を使うと決めた。この問い合わせ方を herdr の表示中のペインで試し、セルの大きさ 14x31 が 1ms 未満で返り、遅れた返事が何も漏れないことを確かめた |
| herdr で隠れている間 | ターミナルのプロセスは窓ではなく herdr-core (hc) が持つ (資料: 窓を閉じても続く)。どこにも表示していない hc のターミナルで、プロセスが止まらずに動き続けることを確かめた。表示していないターミナルの大きさは 120 行 x 200 列 |
| csvlens 0.13.0 | `-t, --tab-separated` がある |
| fx 40.0.1 | `fx <file>` で開く |
| Nerd Font のコードポイント | `glyphnames.json` で確かめた値を Task 1 に書いた |

### Task 3: 種類の分け方と大きさの書き方

**Files:**
- Create: `src/kind.rs`

**Interfaces:**
- Produces:
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum FileKind { Text, Json, Csv, Tsv, Image, Other }`
  - `pub const SNIFF_LEN: usize = 8192;`
  - `pub fn classify(path: &Path, head: &[u8]) -> FileKind` (`head` はファイルの先頭 `SNIFF_LEN` バイトまで)
  - `pub fn format_size(bytes: u64) -> String`
  - `pub fn kind_label(path: &Path) -> String`: 拡張子を大文字で (`PDF`)。拡張子が無ければ `FILE`

分け方 (拡張子は大文字と小文字を区別しない。上から順に決める):
1. `png jpg jpeg gif webp svg bmp` → `Image`
2. `pdf doc docx xls xlsx ppt pptx odt ods odp 3mf kicad_pcb kicad_sch kicad_pro kicad_sym kicad_mod zip tar gz tgz bz2 xz zst 7z rar` → `Other`
3. `json`、またはファイル名が `flake.lock` → `Json`
4. `csv` → `Csv`、`tsv` → `Tsv`
5. `head` が UTF-16 の BOM (`FF FE` か `FE FF`) で始まる → `Text`
6. `head` に NUL がある → `Other`
7. それ以外 → `Text` (YAML、Markdown、拡張子の無いテキスト、UTF-8 でないテキストを含む。`file(1)` と yazi はこれらを `text/plain` とする)

拡張子の無い JSON (`file(1)` では `application/json`) は、中身を全部読まないと決められないので Task 9 の読み込みで `Json` に直す (`is_json_document`、Task 5)。`.jsonl` は `Text` のまま (全体は JSON として読めない。色付けは Task 6 で JSON にする)。

### Task 6: 少しずつの色付け

**Files:**
- Create: `src/highlight.rs`

**Interfaces:**
- Consumes: `TextDoc`、`SyntaxHint` (Task 5)、`theme::TEXT` (Task 1)
- Produces:
  - `pub const PLAIN_THRESHOLD: u64 = 4 * 1024 * 1024;` (これを超えるファイルは色なし)
  - `pub struct Highlighter { syntaxes: SyntaxSet, theme: Theme }`
  - `impl Highlighter { pub fn new() -> Self; pub fn syntax_name(&self, doc: &TextDoc) -> String }`
  - `pub struct HlCache` (1 つの文書の色付けの結果と途中の状態)
  - `impl HlCache { pub fn new(hl: &Highlighter, doc: &TextDoc, plain: bool) -> Self; pub fn line(&self, i: usize) -> Option<&[Span<'static>]>; pub fn done(&self) -> bool; pub fn advance(&mut self, hl: &Highlighter, doc: &TextDoc, budget: Duration) -> bool }`
  - `pub fn plain_spans(text: &str) -> Vec<Span<'static>>` (`theme::TEXT` の 1 つの span)

決めたこと:
- 言語の定義は `two_face::syntax::extra_newlines()`、テーマは `two_face::theme::extra().get(EmbeddedThemeName::CatppuccinMacchiato)`
- 言語の選び方: `SyntaxHint::Json` は名前 `"JSON"`。`SyntaxHint::Path(p)` は `find_syntax_for_file(p)`、無ければ拡張子が `jsonl` か `ndjson` なら `"JSON"` (yazi はこれらを json として扱う。1 行ずつ JSON なので JSON の色付けで合う)、無ければ最初の行で `find_syntax_by_first_line`、無ければ Plain Text
- `advance` は先頭から順に (前の行の `ParseState` と `HighlightState` を持ち越して) 進む。1 行ごとに経過時間を見て `budget` を超えたら止める (少なくとも 1 行は進む)。まだ残りがあれば `true`。syntect には行末に `\n` を付けて渡し、出てきた span からは `\n` を除く。span の文字をつなぐと `doc.lines[i]` と同じになること (折り返しの計算がこれに頼る)
- syntect の色は前景色だけを ratatui の `Color::Rgb` にし、背景は捨てる。太字、斜体、下線は移す
- `plain == true` なら `advance` は何もせず `done()` は真、`line(i)` は `None` (描く側が `plain_spans` を使う)
- 見える範囲を先にするのは、先頭から進むことと、描く側が `line(i)` が `None` の行を色なしで描くことで満たす。位置が下の方に戻ったときも固まらない

振る舞い:
- タブの記憶: `HashMap<Option<String>, TabState { file: Option<PathBuf>, scrolls: HashMap<PathBuf, Scroll> }>`。`file` はそのタブで最後に出していたファイル、`scrolls` はそのタブで見たファイルごとの位置 (設計書: 位置はタブの中でファイルごとに覚え、同じタブで前に見たファイルに戻ったら前の位置から出す)。`tab` が無い状態ファイルは `None` を鍵にする (1 つの状態)
- 表示を別のファイルに移す前 (タブが変わるとき、同じタブでファイルが変わるとき) に、今の表示のパスと位置を今のタブの `file` と `scrolls` に書く
- `on_state_bytes`: 壊れていれば `Action::None` (何も変えない)。`tab` が変わったら、上のとおり書いてから新しいタブに切り替える。`resolve_target`:
  - `Keep` → `Action::None`
  - `Missing` → 表示を `None` にして `Action::None`
  - `Show(p)`: タブが同じで、`p` が表示中 (または読み込み中) のパスと同じなら `Action::None`。違えば、そのタブの `scrolls[p]` があればその位置、無ければ先頭を「読み込み後の位置」として覚え、世代 `gen` を 1 増やして `Action::Load { path: p, gen }`
- `on_loaded`: `gen` が最新でなければ捨てて偽。新しいパスなら「読み込み後の位置」を、同じパスの読み直しなら今の位置を、`clamp` してから使う。`Content::Text` は `HlCache::new(.., plain)` を作って `Body::Text` にする。読み込み中も前の表示は残す (ちらつかない)
- `on_fs_change(path)`: `path` が表示中のパスなら、新しい `gen` で `Action::Load`。それ以外は `None`
- 行の数え方: `Body::Text` は `DocRows { width: text_width(vp.width, lines.len()) }`、`Body::Table` は各行 1 (`Vec<usize>` の 1 の並び)、それ以外はスクロールしない
- キー: `j` / `↓` → 1 行下、`k` / `↑` → 1 行上、`ctrl-d` / `ctrl-u` → `vp.height / 2` (最低 1)、`g` を 2 回続けて → 先頭 (`g` のあとに別のキーが来たら取り消し、その別のキーは普通に扱う)、`G` → `scroll_bottom`、`o` / `Enter` → `Open { alt: false }`、`O` → `Open { alt: true }` (どれも表示が `None` なら `Action::None`)、`ctrl-c` → `Quit`。`q` とその他は `None`。キーを押したら `message` を消す
- `KeyEventKind::Press` 以外は無視する

- Consumes: ここまでのすべて。`parse_args`、`Mode`、`App`、`Action`、`Viewport`、`Body`、`spawn_load`、`FsWatch`、`normalize`、`build_command`、`TextView`、`LinesView`、`header_line`、`info_lines`、`no_file_line`
- Produces: 実行できる `wtr`

組み立て (main.rs の中で関数に分ける。名前は自由):
1. **端末**: `enter()` = raw mode、alternate screen、`EnableFocusChange`、カーソルを隠す。`leave()` はその逆。panic の hook で `leave()` してから元の hook を呼ぶ。`ratatui::init()` は使わず、`Terminal::new(CrosstermBackend::new(stdout()))` を自分で作る (`leave` / `enter` を外のツールのたびに繰り返すため)
2. **画像**: `fn make_picker() -> Picker` を作る。`enter()` のあと、入力のスレッドを始める前に呼ぶ (端末への問い合わせが stdin を読むため)。
   - 環境変数 `TERM_PROGRAM` が `ghostty` のとき: `Picker::from_query_stdio_with_options(QueryStdioOptions { blacklist_protocols: vec![ProtocolType::Kitty, ProtocolType::Sixel], ..Default::default() })` でセルの大きさだけを聞き、`set_protocol_type(ProtocolType::Kitty)` にする。herdr では Kitty の返事が遅れて届き、入力に漏れるので、Kitty の問い合わせは送らない (計画の前に確かめたこと)
   - それ以外: `Picker::from_query_stdio()`
   - どちらも失敗したら `Picker::halfblocks()`。環境変数 `WTR_IMAGE_PROTOCOL` が `kitty` / `halfblocks` なら、その方式を最優先にする (判定が外れたときの逃げ道)
   - 問い合わせのあと、50ms 何も来なくなるまで `event::poll` / `event::read` で入力を読み捨てる (ほかの端末で遅れた返事がキーとして扱われないため)
   - セルの大きさは、隠れたまま起動すると仮の値になる。`Resize` と `FocusGained` のときは、入力のスレッドを `pause()` して `make_picker()` を呼び直し、`resume()` してから画像の protocol を作り直す`Body::Image` を受けたら `picker.new_resize_protocol(img.clone())` で `StatefulProtocol` を作ってメインの側に持ち、`ratatui_image::StatefulImage` で本体の領域に描く
3. **入力のスレッド**: `event::poll(20ms)` → `event::read()` → `AppEvent::Input`。`pause()` / `resume()` を持つ (`Mutex<bool>` + `Condvar` など)。`pause()` はスレッドが poll の外で止まったのを確かめてから戻る。外のツールが動いている間に、このスレッドがキーを横取りしないため
4. **始め方**: `Mode::State(p)` は `p = normalize(p)`、`FsWatch` で `p` を見張り、すぐに `p` を読んで (無ければ空として) `on_state_bytes`。`Mode::File(f)` は `{"file": f}` のバイトを作って `on_state_bytes` に 1 回だけ渡す
5. **ループ**: 描く → `rx.recv_timeout(if 色付けが残っている { 0ms } else { 250ms })` → 来たものを全部 (`try_recv` で溜まった分も) 扱う → `tick_highlight(Duration::from_millis(8))`。見張るファイルは、毎回 `[状態ファイル, app.watched_file()]` で `set_files` する (変わったときだけ)
   - `Fs(paths)`: 状態ファイルが含まれていれば読み直して `on_state_bytes` (読めなければ何もしない)。各パスで `on_fs_change`
   - `Input(Key)`: `on_key`。`Input(Resize)` と `Input(FocusGained)`: 上の 2 のとおり `make_picker()` を呼び直し、`terminal.clear()`、画像があれば `new_resize_protocol` で作り直す (隠れていた枠に戻ったとき、画像を含めて描き直すため)
   - `Loaded`: `on_loaded`。画像なら protocol を作り、画像でなければ捨てる
   - `Action::Load { path, gen }` → `spawn_load(path, gen, tx.clone())`
   - `Action::Open`: `build_command(.., std::env::var_os("PATH").as_deref())`。`Err(m)` は `set_message(Some(m))`。`Ok(cmd)` は 入力の `pause()` → `leave()` → `cmd.status()` → `enter()` → `resume()` → `terminal.clear()` → 画像を作り直す
   - `Action::Quit` → ループを抜けて `leave()`
6. **描き方**: 1 行目は `header_line`。残りが本体で、`Viewport` もこの大きさから作る。`shown()` が `None` なら `no_file_line`、`Body::Text` は `TextView`、`Body::Table` は `LinesView`、`Body::Info` は `info_lines`、`Body::Missing` は `no_file_line`、`Body::Image` は `StatefulImage`
7. 隠れている間も、このループは止めない (spec の「隠れている間」)。herdr ではプロセスは hc が持っていて、隠れても止まらないことを確かめてある。特別なことはしない
