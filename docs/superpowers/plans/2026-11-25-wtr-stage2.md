# wtr 段階 2 (作業履歴) 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 状態ファイルの `session` (または `--session`) の jsonl を追記に追従して読み、道具の呼び出し、指示、要約の区切りを 1 行ずつ並べる作業履歴を作り、一覧と展開 (Edit は delta の差分) を切り替え、`Tab` でファイルの表示と切り替え、`O` で HTML と URL を terminal-browser に開かせ、知らない記録の種類を `wtr scan-records` で数える。

**Architecture:** 段階 1 の crate に足す。jsonl は別スレッドで「前回の位置から末尾まで」を読み、完全な行だけを JSON にして `AppEvent::SessionRead` でメインのループに渡す。`History` (端末に触らない純粋な型) が記録を 1 つずつ受けて行を作り、結果や通知を後から結ぶ。一覧の 1 行の文字 (`row_text`)、展開の中身 (`detail`)、delta の差分 (`diff`)、選択と配置 (`nav`) は別々のモジュールで、`App` がタブごとの表示 (ファイルか作業履歴か) と選択を持つ。terminal-browser は専用のスレッドが順に呼ぶ (TUI を止めない)。

**Tech Stack:** 段階 1 のもの (Rust edition 2024、ratatui 0.30、syntect 5.3 + two-face 0.5、notify 8.2 + notify-debouncer-mini 0.7、serde_json (`preserve_order`, `arbitrary_precision`)、unicode-width 0.2、clap 4.6) に、ansi-to-tui 8.0.1 を足す。外のコマンドは delta 0.20.1 と terminal-browser。

**Spec:** `docs/superpowers/specs/2026-11-20-wtr-design.md` (目標 5〜9、「作業履歴 (段階 2)」、「作業履歴のキー」、「ブラウザーに開かせるとき」、`--on-browse`、`--icon-width`、`Tab`)。段階 1 の計画 `docs/superpowers/plans/2026-11-20-wtr-stage1.md` と、その台帳 `.superpowers/sdd/2026-11-20-wtr-stage1/progress.md` の末尾の parked 3 件も扱う

## Global Constraints

- 段階 1 の Global Constraints のうち、段階 1 だけに限る 2 行 (HTML の `O` は nvim、段階 2 は作らない) を除いてすべて引き継ぐ。cargo は `nix develop -c cargo ...` で動かす
- 固定の文言は英語かマーク。中身として出る文字 (コマンド、指示の文、質問) はそのまま出す。中身の文字はすべて `text_doc::clean_line` を通してから描く (ESC などを画面に流さない)
- 色は catppuccin-macchiato (`theme.rs`)。状態の色: 成功 `GREEN`、失敗 `RED`、拒否 `YELLOW`、中断 `PEACH`、実行中 `SKY` (`#91d7e3`、Task 6 で足す)。指示の行は `BLUE`。小見出しは `OVERLAY1`
- マークは `icons.rs` の 1 か所の表から引く。マークのあとには必ず半角の空白を 1 つ置く。マークの幅は `--icon-width <1|2>` (既定 1)
- jsonl の形は公式に定義されていない。知らない `type`、`subtype`、`attachment.type`、中身の `type`、読めない欄は黙って捨て、落ちない、行が崩れない
- 状態ファイルと jsonl は読むだけ。書かない
- TUI からネットに書かない (Issue を出さない)。`scan-records` は結果を標準出力に出すだけで gh を呼ばない
- delta の引数は呼び出し側で固定し、ユーザーの gitconfig を読まない (`--no-gitconfig`)
- `q` は終了しない。終了は `ctrl-c` だけ

## 決めたこと (設計書が作る人に任せた点、または触れない点)

- 知らない種類を見る起動の印は `--debug-unknown` を作らず、`wtr scan-records <jsonl>` (パスを渡す形) で代える。同じ集計を 2 か所に持たないため。Task 12 で設計書に書く
- 初めての `tab` の値で作業履歴から始めるのは、状態に `session` があるときだけ。無ければファイルの表示から始める (`wtr a.txt` が `no session` で始まらないため)。Task 11 で設計書に書く
- `--icon-width 2` のとき、マークは 2 マスとして数え、マークの右のセルを ratatui の `Cell::set_skip(true)` で描かない
- jsonl の完全な行が JSON として読めないときは、その行を捨てて先へ進む (書きかけではないので待っても直らない)
- 持ち越しの deferred minor のうち、この計画で直すのは `TabState.file` の `dead_code` だけ (段階 2 でも読む所が無いので欄ごと消す)。それ以外は段階 2 の入力に関わらないので台帳に残す

## Review Focus

1. jsonl の最後の行が書きかけのまま読まれ、そのあと残りが書き足される。その呼び出しが抜けず、二重にもならないこと (Task 3 の試験)。読み込みの最中に追記が来ても取りこぼさないこと (Task 11 の試験)
2. 記録の順が入れ替わる: `tool_result` が `tool_use` より先、hand-back が Agent の `agentId` より先、背景の Agent の完了通知が何度も来る。どれも元の行に結ばれ、最後の通知の状態になること (Task 4、Task 5 の試験)
3. 同じタブで `session` が別の jsonl に変わる (`/clear`)、または jsonl が短く書き直される。読み直し、選択と展開を捨てて一番下から出ること (Task 3、Task 11 の試験)

### Task 1: 見張りの直し (段階 1 の parked 3 件) と `TabState.file` の除去

parked の 3 件: (1) 親のフォルダが無いパスを見張ると、`set_files` が失敗し続け、毎ターン FSEvents の流れを作り直す。(2) 親が無いパスは `normalize` で `/private` に直らず、後でできても届くパスと合わない。(3) リンクの途中の段が別のフォルダにあると見張られず、リンクを張り替えた直後の書き込みを取りこぼす。

**Files:**
- Modify: `src/watch.rs`、`src/main.rs` (`sync_watch`)、`src/app.rs` (`TabState`)

**Interfaces:**
- Produces:
  - `pub fn normalize(p: &Path) -> PathBuf`: 親から上へたどって最初に在る祖先を canonicalize し、残りの部分をつなぎ直す (親が在れば今までと同じ結果)
  - `pub fn link_chain(p: &Path) -> Vec<PathBuf>`: `normalize(p)` から始めてリンクを 1 段ずつたどった全段 (最後が `link_target(p)`)。`link_target` はこれの最後の要素を返すように書き直す
  - `FsWatch::set_files(&mut self, files: &[&Path]) -> notify::Result<bool>`: 各ファイルについて、`link_chain` の全段の親を見張る。親が無ければ、在る一番近い祖先を代わりに見張り、それを「代わり」として覚える。戻り値は、前の呼び出しにも在ったファイルのうち、見張るフォルダの組が前と変わったものが 1 つでもあれば `true`
  - `FsWatch::take_resync(&self) -> bool`: 「代わり」のフォルダの直下で変化があった (フォルダができたかもしれない) ことを、1 回だけ返す (`Arc<AtomicBool>` を callback と分け合う)
  - リンクの対応 (`links`) は、途中の段と最後の段のどちらのパスにも、元のパスを結ぶ

### Task 3: jsonl の追記分の読み取り

**Files:**
- Create: `src/tail.rs`
- Modify: `src/lib.rs`、`src/event.rs`

**Interfaces:**
- Produces:
  - `pub struct Chunk { pub records: Vec<serde_json::Value>, pub end: u64, pub reset: bool }`
  - `pub fn read_from(path: &Path, offset: u64) -> io::Result<Chunk>`: ファイルの長さが `offset` より短ければ `reset: true` にして 0 から読む。`offset` (または 0) から末尾までを読み、最後の `\n` までの完全な行だけを JSON にする。読めない行と空行は捨てる。`end` は最後の `\n` の次のバイト (完全な行が無ければ読み始めの位置のまま)
  - `pub struct SessionRead { pub generation: u64, pub result: io::Result<Chunk> }`
  - `pub fn spawn_read(path: PathBuf, offset: u64, generation: u64, tx: Sender<AppEvent>)`: 名前 `session` のスレッドで `read_from` を呼び、`AppEvent::SessionRead(SessionRead)` を送る。panic は `catch_unwind` で受け、`Err(io::Error::other("panicked"))` を送る (loader と同じ考え方)
  - `event.rs`: `AppEvent::SessionRead(crate::tail::SessionRead)` を足す

```json
{
  "files": 120,
  "records": 45678,
  "unknown": [
    { "kind": "attachment:brand_new", "count": 3, "first_version": "2.1.330", "fields": ["prompt", "type"] }
```

  - `missing_fields`: `FIELDS` の種類に当たる記録で、その JSON Pointer が無いもの。`tool:<名前>` は、同じファイルの `tool_use` の id から名前を引き、`toolUseResult` が物の user の記録だけを見る。`last_version` は無かった記録の `version` の一番大きいもの
  - 記録の中身 (文、コマンド、パス) は出さない
